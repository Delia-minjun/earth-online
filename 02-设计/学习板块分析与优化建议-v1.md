# 地球 Online · 学习板块分析与优化建议 v1

日期：2026-11-15  
适用对象：本人使用的「地球 Online」学习板块。  
目标：帮助使用者从零开始，逐步掌握自己想学习的技能或知识点。  
文档性质：现状分析与产品优化建议，不代表相关功能已经实现。

## 1. 核心判断

学习板块应逐步形成一套能够**教人入门、带人练习、诊断困难、验证掌握**的学习系统。

现有功能已经具备资料整理、卡片生成和间隔复习的基础，但从零学习需要的教学过程尚不完整。系统可以生成内容，却还难以持续回答：

- 我现在应该学什么，为什么先学这个？
- 我需要哪些基础，缺少的基础如何补上？
- 我哪里没有学会，下一次应该怎样练？
- 我能否不看答案独立完成？
- 过一段时间后，我还能否完成？
- 换一个问题或真实情境，我能否应用？

建议围绕以下闭环组织功能：

> 明确目标 → 检查基础 → 学习讲解与示例 → 在指导下练习 → 独立作答 → 得到反馈并修正 → 延迟检验 → 实际应用 → 推荐下一步。

卡片、资料、题库、AI讲解和统计都服务于这个闭环。

### 2.2 研究如何用于设计

本文区分三种结论：

1. **研究支持的学习原则**：例如提取练习、间隔学习、例题学习、自我解释和有效反馈。
2. **由原则推导的产品建议**：例如独立作答入口、补救流程、掌握证据和下一步推荐。
3. **需要试用的具体参数**：例如一个单元多长、一次做几题、几天后再测。

研究支持某个原则，不等于证明本文提出的全部页面和产品机制有效。不同领域、已有基础与学习目标会影响效果；应通过个人试用和独立表现进行验证。

## 3. 当前功能的主要缺口

当前主要流程是：

> 创建科目 → 上传资料 → 按章节生成知识卡或练习题 → 翻面查看答案 → 自评 → 到期复习。

| 当前实现 | 对从零学习的限制 | 优化方向 |
|---|---|---|
| 创建科目后主要入口是上传资料 | 不知道教材和学习顺序时难以开始 | 增加目标定义与学习路径 |
| 按章节生成知识卡、练习题 | 章节顺序不一定等于适合本人的教学顺序 | 加入先备知识、能力目标与难度递进 |
| 知识卡与练习题最终使用正反面卡片结构 | 难以承载解题步骤、代码、作品和实际操作 | 区分学习活动与练习类型 |
| 翻面后自评，不记录实际答案 | 无法区分独立完成、看懂答案和依靠提示完成 | 保存作答与辅助程度 |
| 用五档间隔安排复习 | 对新学不会的内容，补救过程不足 | 分开新学、补救与长期保持 |
| 主要记录次数与自评档位 | 缺少实际表现和迁移证据 | 建立知识点级学习证据 |
| 满十张复习记录发币 | 卡片数量可能成为替代目标 | 奖励有效学习行动，掌握另行判断 |

当前排程常量为1、3、7、21、60天；自评“不会”回到第一格，“会”进一格，“简单”进两格。它可作为记忆复习基础，但还不足以承担完整教学。

需求文档已经提出“输入主题 → 生成可编辑路径 → 接入学习与测验”的自学设想。在本次读取的页面与路由中，尚未看到完整落地；可以沿着已有产品目标继续深化。

## 4. 建议一：从可检验的学习目标开始

### 4.1 创建学习项目

输入尽量简短：

- 想学习什么，以及希望用它做什么；
- 已有基础，允许选择“完全没有”；
- 每周大致可投入时间；
- 是否有期限。

系统帮助把兴趣描述转化为可确认的能力目标。例如：

> 原始兴趣：学习Python。  
> 可检验目标：独立写一个脚本，读取自己的账单，按类别汇总每月支出。

也可以是概念性目标，例如：

> 能用自己的话解释条件概率，辨别两个常见误解，并解决一个简单应用问题。

不直接承诺“精通”，先明确这次学习的范围和完成标准。

### 4.2 检查先备知识

用少量低压力问题检查相关基础，允许“不知道”，也允许零基础者直接进入入门教学。

诊断结果只用于决定从哪里开始，不作为惩罚或能力标签。某一题失败不足以证明缺少某个基础，应通过补充问题或实际练习确认。

### 4.3 学习路径的最小结构

| 字段 | 示例 |
|---|---|
| 学完能做什么 | 遍历交易并累加金额 |
| 需要的基础 | 变量、列表、基本运算 |
| 教学材料 | 一小段可靠教程与一个完整示例 |
| 练习方式 | 补全代码，再完成变式 |
| 验证方式 | 不看示例，处理另一组交易 |

路径应可编辑，并允许根据表现补基础、跳过已会内容和调整顺序。不要一次生成大量章节后，将完成路径的管理工作全部交给使用者。

## 5. 建议二：为新手提供讲解、示例和逐步减少的指导

### 5.1 研究依据

例题学习研究支持在适当条件下让新手学习完整解题示例，再逐步过渡到独立解决问题。已有知识会影响指导需求；随着熟练程度上升，应减少不再需要的指导。[例题学习研究综述，2010](https://link.springer.com/article/10.1007/s10648-010-9134-7)

### 5.2 单元教学结构

1. **简短讲解**：是什么，为什么要学，解决什么问题。
2. **完整示例**：展示关键过程，解释选择依据。
3. **补全练习**：由学习者完成部分步骤。
4. **独立练习**：完成一个相似但不同的问题。
5. **应用练习**：放入稍有变化的情境中使用。

以循环为例：

> 看懂计算总金额的示例 → 补全累加步骤 → 独立统计超过100元的交易 → 用于自己的账单。

不是每个知识点都必须经过完全相同的五步。熟悉的内容可以跳过示例；困难内容可以回到更小的步骤。这里的单元安排是设计提案，需要试用。

## 6. 建议三：把翻面自评升级为实际提取与解释

### 6.1 研究依据

提取练习要求先从记忆中组织答案，再查看资料或反馈。课堂研究的系统综述发现，它在多种学科、教育阶段和测试形式中能够改善学习表现。[Agarwal等，2021](https://link.springer.com/article/10.1007/s10648-021-09595-9)

自我解释指学习者解释因果、概念关系或解题理由。相关元分析支持这类活动的学习价值；产品应引导解释关系，而不是只让人复述定义。[Bisra等，2018](https://link.springer.com/article/10.1007/s10648-018-9434-x)

### 6.2 作答方式

| 内容 | 作答方式 |
|---|---|
| 概念 | 用自己的话解释，给一个例子或反例 |
| 计算 | 输入结果和关键步骤 |
| 编程 | 提交代码，查看测试结果 |
| 简单事实 | 输入关键词，或口述后自检 |
| 完全不会 | 选择需要讲解，进入补救 |

不强迫每张卡写长答案，但至少区分：独立完成、提示后完成、查看答案、未能完成。

适合加入的解释问题：

- 为什么这里可以使用这个方法？
- 它与另一个容易混淆的概念有什么区别？
- 什么情况下这个结论不成立？

自评保留为主观信心信息，不直接代替实际表现。本人说“懂了”可以作为反馈，但不足以单独判定掌握。

## 7. 建议四：按知识和技能类型设计练习

| 学习对象 | 主要练习 | 掌握证据 |
|---|---|---|
| 事实、术语、公式 | 闭卷回忆、间隔复习 | 延迟后仍能正确提取 |
| 概念、理论 | 解释、比较、举例、反例 | 能说明关系和适用边界 |
| 解题与操作方法 | 示例、补全、独立练习、变式 | 能选择方法并完成过程 |
| 综合技能 | 小作品、实际任务、评价标准 | 能交付符合要求的成果 |

例如，记住构图原则可以使用卡片，拍出符合意图的照片则需要实际拍摄和作品反馈。编程、写作、语言表达等也需要与目标相符的练习。

### 7.1 在掌握基础后使用交错练习

混合相关且容易混淆的题型，让学习者判断应该使用哪种方法，而不是一直重复同一套路。不要把交错练习等同于随机切换所有科目。

一项2026年的中小学真实课堂元分析发现，提取、间隔和交错练习具有平均收益，但效果受任务、测试形式、反馈等条件影响。其研究对象不是本人的个人软件学习情境，因此不能直接承诺同等效果。[Ruitenburg等，2026](https://link.springer.com/article/10.1007/s10648-026-10225-5)

产品建议：先允许同类练习建立基础，再增加需要辨别方法的混合练习；通过延迟表现判断是否有帮助。

## 8. 建议五：错误之后提供具体反馈与补救

### 8.1 研究依据

教育反馈的元分析显示，反馈对学习的效果与其提供的信息内容有关，不同形式的反馈存在明显差异。因此，分数、“回答错误”或泛泛鼓励不能等同于有效教学。[Wisniewski等，2020](https://pubmed.ncbi.nlm.nih.gov/32038429/)

### 8.2 建议流程

> 尝试作答 → 指出已做对的部分 → 定位具体错误 → 解释或补充示例 → 再次尝试 → 用变式检查。

反馈示例：

> 方法选对了，但把每笔交易金额和累计金额混用了。先看看两个变量在一次循环中如何变化，再完成一道补全题。

建议将困难初步区分为：

- 概念理解存在误解；
- 先备知识不足；
- 方法选择不合适；
- 执行步骤出错；
- 问题理解或表达存在歧义；
- 题目、参考答案或AI判定本身可能有问题。

错误结果与错误原因要分开。系统可以发现结果不符合要求，但原因应标为待确认的推测，必要时通过追问验证。

### 8.3 AI与内容质量

- 教学和答案保留可追溯来源；来源未核实的内容明确标记。
- 编程尽量用测试验证，客观题使用核验答案，开放作品使用可见评价标准。
- 允许本人指出题目错误、接受合理的不同解法、修改评分。
- 提供完整讲解与提示梯度，不强制一直猜答案。
- 不根据一次失败就反复生成同样内容；必要时改变示例、讲解粒度或练习形式。

这些属于可靠教学所需的产品约束，不表示当前AI评分已有经验证的准确性。

## 9. 建议六：分开新学、补救与长期保持

### 9.1 研究依据

间隔学习的元分析支持将学习分散到不同时间，但合适间隔与希望保持多久等条件有关。固定的日期序列不能视为适用于所有材料的最优公式。[Cepeda等，2006](https://pubmed.ncbi.nlm.nih.gov/16719566/)

### 9.2 建议排程行为

| 学习表现 | 下一步 |
|---|---|
| 刚学还不会 | 补救讲解，本次学习稍后再尝试 |
| 当场独立完成 | 之后安排延迟检验 |
| 延迟后仍能完成 | 逐渐延长间隔 |
| 反复出错 | 检查先备知识、题目质量和教学方式 |
| 能记住但不会应用 | 增加变式与实际任务 |

事实可以重复提取；方法和概念需要不同表述、例子、反例或变式。不要让原题熟悉度代替实际掌握。

首轮可以保留简单排程，优先补齐教学、作答和反馈；暂不把替换复杂排程算法作为主要工作。

## 10. 建议七：用证据记录掌握，分开投入与奖励

### 10.1 知识点级证据

| 记录 | 含义 |
|---|---|
| 看过讲解 | 已接触内容 |
| 有提示完成 | 在辅助下可以完成 |
| 独立完成 | 当前可以自己完成 |
| 延迟检验通过 | 一段时间后仍能完成 |
| 新情境应用 | 能用于不同问题或真实任务 |

这些是可以并存的证据，不必强行压成一条等级。一个概念可能记忆稳定，但应用仍需帮助。界面应保留最近验证日期与证据来源，不把一次通过解释为永久掌握。

首版不需要复杂的掌握概率模型，也不宜用来源不明的“掌握度85%”制造精确感。

### 10.2 最少需要保存的数据

- 学习目标与对应知识点；
- 题目或任务、答案或评价标准；
- 本人的实际作答或作品；
- 是否看过答案、用了多少提示；
- 结果、反馈和后续补救；
- 时间、是否属于延迟检验或变式应用。

数据只记录教学决策需要的内容，不要求每一步都写笔记或上传证据。

### 10.3 与生活游戏化的衔接

| 数据 | 用途 |
|---|---|
| 学习时间、成长经验 | 记录投入 |
| 快乐币 | 奖励有效尝试、完成练习和纠正错误等行动 |
| 掌握证据 | 根据作答、延迟检验与作品更新 |

不按单纯正确率发主要奖励，避免只做简单题；不把看过答案、复习次数或学习时长直接换算成掌握。

同一次学习在任务、专注和练习中可以有多种过程记录，但应按统一行动结算规则避免重复发币。此处与[生活游戏化设计计划](生活游戏化设计计划-v1.md)衔接。

## 11. 页面与交互建议

### 11.1 学习首页

优先展示一个明确的下一步：

> 下一步：学会用循环汇总金额  
> 预计约25分钟 · 一个示例、一个补全练习、一个独立任务  
> 开始学习

时间和练习数量是示例，不是研究规定的最佳参数。

辅助入口保留：

- **学习路径**：目标、当前位置、先备知识、阶段验证。
- **复习与薄弱点**：需要保持、补救或重新验证的内容。
- **资料与管理**：上传资料、管理来源、卡片和题目。

继续沿用系统简洁的米白、鼠尾草绿和卡片视觉。教学过程在独立学习界面中进行；任务设置、资料管理、证据详情使用弹窗或抽屉，避免首页堆满新卡片。

### 11.2 一次学习会话

> 说明本次目标 → 必要的旧知回忆 → 新内容与示例 → 引导练习 → 独立尝试 → 反馈与修正 → 保存下一次安排。

零基础内容可跳过旧知回忆，熟悉内容可减少讲解。使用者可以请求讲解、暂停或缩小任务，不要求每次完成固定时长。

### 11.3 下一步推荐应可解释

例如：

- “上一题在变量更新步骤需要提示，先完成一个补全练习。”
- “上次已独立完成，今天用一个变式检查是否保持。”
- “本单元已经有独立与延迟证据，可以进入下一单元。”

允许本人换一个任务或继续原计划。推荐提供帮助，不形成强制路线。

## 12. 完整示例：从零学会账单汇总脚本

此例用于说明闭环，不代表本人已经选择学习编程。

| 阶段 | 学习内容 | 练习与验证 |
|---|---|---|
| 定义目标 | 读账单并按类别汇总 | 确认输入格式与预期结果 |
| 建立基础 | 变量、列表、数值运算 | 解释变量含义，完成小操作 |
| 学会循环 | 逐条读取、累加 | 完整示例 → 补全 → 独立变式 |
| 学会分类 | 条件判断、类别归组 | 根据新交易选择处理方式 |
| 综合应用 | 读取文件、输出汇总 | 先用示例数据，之后处理另一份数据 |
| 延迟验证 | 不重看完整答案 | 修改需求、找错或处理新的输入 |

如果某一步卡住，系统回到相关基础或补充示例；如果已经会了，允许跳过。最终以独立完成的脚本和验证记录作为结果，卡片用于记忆确实需要记住的概念。

## 13. 实施优先级

### 第一轮：做出一个真正完整的小闭环

先支持一个具体学习目标和一种主要练习类型。

1. **目标与小路径**：明确能力目标、先备知识、少量单元与验证标准。
2. **教学与实际作答**：讲解、示例、引导练习、独立回答。
3. **反馈与补救**：记录实际表现，提供有针对性的下一次尝试。
4. **延迟检验与推荐**：下一次回来时承接上一次表现。

优先考虑能较可靠验证的内容类型，例如编程或数学中的独立解题。完成一种类型后，再扩展作品评价、语言表达等其他任务。

### 第二轮：提高个性化与保持效果

- 根据提示使用情况调整指导强度；
- 知识点级证据与先备知识关联；
- 变式与相关题型交错练习；
- 复习负担管理和更精细排程；
- 与周计划、主线和奖励结算衔接。

### 暂不优先

- 一次生成大量课程、卡片和题库；
- 没有验证依据的精确掌握百分比；
- 复杂技能树与排名；
- 单纯增加AI聊天入口；
- 在缺少有效作答数据时引入复杂自适应模型。

## 14. 如何判断优化是否有效

选一个本人确实想学的小目标，用两周或一个合适阶段做试用。主要看实际表现，不以使用时长和卡片数量作为成功标准。

| 问题 | 建议观察 |
|---|---|
| 更容易开始了吗？ | 打开后是否知道下一步做什么 |
| 能独立完成了吗？ | 未看答案时的表现和提示使用情况 |
| 过几天还会吗？ | 延迟检验，尽量使用未直接练过的变式 |
| 能应用了吗？ | 与目标相符的小任务或作品 |
| 错误后有改善吗？ | 补救后是否能再次完成 |
| 负担合适吗？ | 记录与配置是否占用过多时间 |

同一道题反复答对可能反映熟悉，不能单独说明迁移。个人前后表现也受时间投入、材料和任务难度影响，不应直接解释为严格的因果证明。

## 15. 研究来源与适用边界

以下是本次建议引用的研究。表中的产品转化属于本文推导。

| 研究 | 支持的原则 | 适用边界 |
|---|---|---|
| [Agarwal、Nunes与Blunt，2021：课堂提取练习系统综述](https://link.springer.com/article/10.1007/s10648-021-09595-9) | 主动提取可以支持学习与保持 | 不能据此推断只做背记卡就能掌握所有综合技能 |
| [van Gog与Rummel，2010：例题学习研究综述](https://link.springer.com/article/10.1007/s10648-010-9134-7) | 根据已有知识使用示例，逐步转向独立解决问题 | 指导需求随熟练程度变化，不能一律让人一直看例题 |
| [Bisra等，2018：自我解释元分析](https://link.springer.com/article/10.1007/s10648-018-9434-x) | 解释因果、概念关系和解题理由具有价值 | 复述与长篇笔记不自动等于有效解释 |
| [Wisniewski、Zierer与Hattie，2020：反馈元分析](https://pubmed.ncbi.nlm.nih.gov/32038429/) | 反馈效果与所传达的信息有关 | 不同反馈形式差异大；不证明AI自动评分可靠 |
| [Cepeda等，2006：分散学习元分析](https://pubmed.ncbi.nlm.nih.gov/16719566/) | 分散学习、间隔与保持目标之间存在关系 | 不支持对所有内容采用同一个最优间隔序列 |
| [Ruitenburg等，2026：真实课堂中的提取、间隔、交错练习元分析](https://link.springer.com/article/10.1007/s10648-026-10225-5) | 三类练习的收益与任务和实施条件有关 | 研究集中于中小学课堂，不能直接外推到所有成人技能与个人软件 |

产品设计应以这些原则作为起点，通过可靠资料、实际练习、可解释反馈和个人试用，逐步形成适合本人的学习流程。

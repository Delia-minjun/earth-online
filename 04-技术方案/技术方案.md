# 技术方案 · 分阶段开发计划

> 对应需求：`01-需求/需求规格.md`（含 §11 番茄钟、§12 音乐）
> 目标机器：Windows 11，单用户，本地优先，架构预留上云。

---

## 1. 一页结论

| 决策 | 结论 |
|---|---|
| 形态 | **本地 Web 应用**（浏览器访问 `127.0.0.1`）+ 后期套 **Electron 桌面壳** |
| 语言 | TypeScript 全栈，单一仓库 |
| 前端 | React 19 + Vite + Tailwind CSS + 自研组件（不引重型 UI 库） |
| 后端 | Node 24 + Hono（轻量 HTTP）+ `node:sqlite`（内置，免原生编译） |
| 数据 | SQLite 单文件 `data/life.db`，手写 SQL + 编号迁移脚本 |
| 多端 | PWA（手机/平板）+ 响应式；通过 Tailscale 组网访问 |
| 同步 | 服务端权威 + 客户端离线队列 + 逐条幂等 upsert |
| 桌面壳 | Electron（含托盘、开机自启、媒体键模拟） |
| 备份 | 每日 SQLite 快照 + 私有 Git 仓库 |
| 不引入 | Next.js（不需要 SSR）、ORM（避免原生依赖）、CRDT（单用户用不上） |

**为什么不选 Tauri**：Tauri 更小更快，但需要 Rust + MSVC 构建工具链，你这台机器都没有；Electron 只要 Node 就能跑。等将来嫌体积大再迁。

**为什么不用 Next.js**：这是本地单用户应用，没有 SEO、没有服务端渲染需求、也不需要部署到 Vercel。Next 带来的构建复杂度和启动开销都是净负担。

## 2. 架构

```
┌─ 手机 PWA ─┐
├─ 平板 PWA ─┼── HTTPS（tailnet）──┐
├─ 电脑浏览器 ┤                     ├──> Node 服务 (127.0.0.1:7788)
└─ 桌面壳 ────┘                     │        │
   (Electron)                        │        ├──> SQLite  data/life.db
                                     │        ├──> 文件库  data/files/（学习资料）
                                     │        ├──> LLM API（可选，学习 Agent）
                                     │        └──> 快照    data/backups/
                                     └── 同一份数据，服务端权威
```

一个 Node 进程同时是「API 服务 + 静态文件服务」。手机、平板、电脑、桌面壳都指向它，**不存在多副本**，同步问题因此从「多端合并」降级为「离线补传」。

### 2.1 部署位置（已定：先本机，保留升级路径）

- 服务跑在本机 `127.0.0.1:7788`；外出访问走 **Tailscale 虚拟局域网**，**不要求同一 WiFi**。
- 已知代价（接受）：电脑关机时，手机上的写入进本地队列、可写不可同步，提醒不触发；数据不会丢。
- **迁移路径**：部署单元 = 一个 Node 进程 + 一个数据目录（`life.db` + `files/`）。换机器 = 拷文件夹 + 启动进程，不改代码。
- **决策点**：连续使用两周后再判断是否需要升级到「家里常开设备（旧笔记本/迷你主机/NAS）」或「云服务器」。升级优先级：常开设备 > 云服务器（数据自主、无月费）。
- 若"提醒必须准时"成为硬需求，则常开设备从可选变为必需（PWA 本地通知在无推送服务器时不可靠）。

### 2.2 客户端形态（已定）

| 端 | 现在 | 后期 |
|---|---|---|
| 电脑 | 浏览器标签页 | **Electron 桌面应用**（P7）：托盘、开机自启、全局快捷键、控制音乐 |
| 手机（HarmonyOS 4.2，兼容安卓） | **PWA 添加到桌面** | **Capacitor 打包 apk**（P8 之后，按需） |
| 平板 | PWA | 同手机 |

- 三种壳共用**同一份前端代码**，套壳不重写业务逻辑。
- 鸿蒙 4.2 基于 AOSP，可直接侧载 apk（需在系统里允许"未知来源应用"）。
- 打包 apk 的额外工具：Android Studio（免费）+ Capacitor（免费）；不上架应用商店，自用侧载即可。
- 开发期仍以浏览器为主：改一行代码立刻可见，套壳留到最后，成本约半天。

## 3. 选型与取舍

| 层 | 选择 | 备选 | 为什么 |
|---|---|---|---|
| 构建 | Vite | webpack / Next | 快，配置少 |
| 前端框架 | React 19 | Svelte / Vue | 生态与 AI 生成代码的准确率最高；你会让我和子模型一起写，这点很重要 |
| 样式 | Tailwind + CSS 变量令牌 | 组件库（Ant/MUI） | 莫兰迪色板与「去表格线」的设计需要完全可控，组件库会带一堆默认样式来对抗 |
| 图标 | Lucide | 自绘 SVG | 线条风格统一，免费 |
| 后端 | Hono | Express / Fastify | 极轻、类型好、单文件路由、无依赖包袱 |
| 数据库 | `node:sqlite`（Node 24 内置） | better-sqlite3 | **零原生编译**。better-sqlite3 要匹配 Node ABI 的预编译包，装不上就得装 VS Build Tools（几个 GB） |
| 数据访问 | 手写 SQL + zod 校验 | Drizzle / Prisma | 单用户 20 张表，SQL 完全可控；ORM 的迁移抽象反而是负担 |
| i18n | i18next + 自建语言包 | 自研 | 成熟、支持命名空间、能配术语表 |
| 状态 | TanStack Query + 少量 Zustand | Redux | 服务端状态与本地 UI 状态分开，别混 |
| 离线存储 | IndexedDB（idb 库） | localStorage | 容量与结构化需要 |
| PWA | vite-plugin-pwa | 手写 SW | 自动生成 manifest 与预缓存 |
| 桌面壳 | Electron | Tauri | 无需 Rust 工具链 |
| 媒体控制 | 模拟媒体键（`keybd_event`） | Windows SMTC（WinRT） | 媒体键几十行代码、稳定；SMTC 能读歌名但要走 WinRT 绑定，留作增强项 |
| 测试 | Vitest + Playwright | Jest | 与 Vite 同源 |

## 6. 同步与离线

单用户、单服务，冲突面本来很小。策略：

1. **服务端权威**：所有写入先落服务端；客户端生成 `id`（uuid v7），重复提交天然幂等。
2. **离线队列**：IndexedDB 中存 outbox，联网后按顺序重放；每条带 `client_ts`。
3. **拉取**：`GET /sync?since=<seq>`，服务端维护自增 `seq`，返回变更集。
4. **冲突**：
   - 逐条记录（打卡、记账、体重、待办勾选）——`upsert`，后到覆盖，无冲突可言。
   - 文本块（复盘、随手记）——若两份都改过，**保留两版**写入 `revision`，界面提示「有 2 个版本，选择保留哪个」。
5. **互斥**：番茄钟与专注计时同一时刻只允许一个（服务端记 `active_pomodoro`）。
6. **离线白名单**：只有打卡、随手记、记账、体重、勾选待办、快速捕获走离线队列；时间轴与复盘要求在线。

## 7. 安全与备份

- 单用户，本地默认免登录；一旦开启 tailnet 访问，强制一个 6 位 PIN + 长期 token（Cookie），失败 5 次锁 10 分钟。
- 数据库不做加密（本地个人数据，加密会毁掉「用 SQLite 工具直接读」的便利）；敏感文件（学习资料）与数据库分离存放。
- 每日 03:00 用 SQLite `VACUUM INTO` 做快照，保留 14 天；每周推一次到私有 Git 仓库（`.gitignore` 排除 db 与 files）。
- 提供「一键导出」为 JSON + CSV（备份用，不是日常功能）。

## 8. 分阶段计划

> 工作量单位：人日（含自测）。**P0–P3 是不可跳过的脊柱**，P4 之后可以按兴趣插队。

### P0 · 脚手架（0.5–1 人日）

**做什么**
- 建 monorepo、TS 配置、Vite、Tailwind（写入 §10 色板为 CSS 变量）
- i18n 骨架（`zh-CN` / `en-US` 两个语言包，切换按钮）
- Hono 服务 + `node:sqlite` 连接 + 迁移脚本机制（`migrations/001_init.sql`）
- 一条健康检查接口 + 一个「今日」空页面渲染莫兰迪配色
- Vitest 与 Playwright 各跑通一个用例

**验收**：`pnpm dev` 起来，浏览器能看到空壳页面，切换语言生效，`GET /api/health` 返回 ok，`data/life.db` 自动创建。
**风险**：`node:sqlite` 在 Node 24 上会打印 experimental 警告——忽略即可；若真不可用，回退 better-sqlite3。

---

### P1 · 核心闭环 MVP（5–8 人日）

**做什么**
- 周实体与周切换（ISO 周、跨月跨年）
- 任务 / 项目 / 领域 三级结构 + 今日任务
- 时间块：**列表录入**（P1 表单式，不做拖拽）
- 习惯 + 打卡网格
- 日/周复盘（四象限自由文本 + 自动数据摘要）
- 随手记（按天）
- 单机运行，无登录

**验收**：能用它真实规划一周并复盘，替换掉现在的 Excel。
**依赖**：P0。

---

### P2 · 记录类模块（3–4 人日）

**做什么**
- 收支（类别、月度预算、超支提示）
- 体重曲线、饮食记录、健身日标签
- 类别字典（原表 5 类 + 自定义颜色）
- 月历视图（高亮本周/今天，点日期跳周）

**验收**：需求文档 §1 表格的 15 项，除「打印」外全部可用。
**依赖**：P1。

---

### P3 · 奖惩经济 + 番茄钟（3–4 人日）

**做什么**
- 币价目表（可配）、账本、奖赏商店、兑换（自动记账联动）
- 六领域进度条 + 每日衰减结算任务（Node 定时器 / 启动时补算）
- 番茄钟：时间戳计时、后台运行、结束确认、**自动写时间块**、跨端互斥
- 每日结算脚本：算币、算衰减、写 `area_progress`

**验收**：跑一周，币能挣能花、进度条会掉；番茄钟记录能出现在时间轴里。
**依赖**：P1（时间块）、P2（记账联动）。

---

### P4 · 多端 + 同步 + 离线（5–8 人日）

**做什么**
- 手机/平板响应式布局（对照 `02-设计/原型/02-今日-手机.png`）
- PWA（manifest、离线缓存、安装引导）
- 手机端兼容目标：HarmonyOS 4.2（Chromium 内核浏览器），桌面图标 + 独立窗口
- 首个可安装版本验收：手机浏览器菜单「添加到桌面」后，图标可全屏打开
- 离线队列 + `/sync` 增量拉取 + 冲突兜底
- 单用户 PIN 登录 + token
- Tailscale 组网 + `tailscale serve` 提供 HTTPS（PWA 必须 HTTPS）

**验收**：手机扫码装到主屏；飞行模式打卡，恢复网络自动补传；电脑改的数据手机上能看到。
**依赖**：P1–P3 全部。
**风险**：这是全项目最复杂的一段，预留返工时间。

---

### P5a · 学习 Agent（7–10 人日）

**做什么**
- 科目 / 章节 / 资料上传（PDF、PPTX、DOCX、图片、文本、链接）
- 文本抽取：`pdf-parse`、`mammoth`、`pptx` 解析
- OCR：打印体走本地 `tesseract.js`；手写走多模态 API（需付费，见 §9），**必须经过校对页**
- 分段摘要 → 知识点卡片 → SRS 队列（1/3/7/21 天）
- 出题：考前模拟（整套+计时+批改）与背记卡片，共用题目数据
- 错题本、掌握度、薄弱章节
- API 分级调度：flash 类做摘要与格式转换，pro 类做难题与批改；结果落库缓存，不重复调用
- **顺手做掉 Agent 抽象层**（§12，约 0.5 人日）

**验收**：上传一学期一门课的资料，能生成卡片、能出一套卷子并批改。
**依赖**：P2（科目可挂领域）、P4（手机刷题）。
**风险**：OCR 质量与成本；出题必须带出处，否则不可用。

---

### P5b · 自学模块（4–6 人日）

**做什么**
- 输入：主题 + 目标深度 + 每周可投入时间（+ 期限、已有基础）
- 生成 3–6 阶段的学习路径，**落成可编辑的科目结构**，用户确认后才入库
- 可选联网检索：检索结果带链接；无检索时全部标注「AI 生成，未核实」
- 每个阶段生成知识卡与小测，直接进 P5a 的 SRS 与错题体系
- 阶段完成度 → 联动周计划（排时间块）与奖赏经济（发币）

**验收**：输入一个没学过的领域，能在 2 分钟内得到一份可编辑的路径，并开始学第一阶段。
**依赖**：P5a（复用卡片与测验）。
**风险**：大纲容易「看着专业但没营养」——所以强制用户确认 + 可编辑，是产品红线。

### P6 · 双语（2–3 人日，贯穿全程）

**做什么**
- P0 起每加一个界面就补两套文案（**这是纪律，不是阶段任务**）
- 术语表导入（Excel/CSV/Word/Markdown）
- 点词查义（术语表优先 → 词典降级）→ 生词本 → 进 SRS 队列
- AI 输出跟随界面语言

**验收**：切到英文后界面无中文残留，点任意单词能查义并加卡。
**依赖**：P0 开始，P6 收尾。

---

### P7 · 桌面壳 + 音乐（3–5 人日）

**做什么**
- Electron 壳加载 `127.0.0.1:7788`，托盘、开机自启、全局快捷键唤起快速捕获
- 媒体键模拟（播放/暂停/上一首/下一首）
- 歌单书签：动作类型（开 App / 开网页 / 复制链接 / 控制播放）+ 失败降级
- 番茄钟联动：专注开始 → 触发歌单动作，休息 → 暂停
- 可选增强：SMTC 读当前歌名（做不动就砍）

**验收**：桌面壳里点一下能控制酷狗播放/暂停；专注结束自动停。
**依赖**：P3（番茄钟）。
**风险**：`kugou://` 协议是否可用未知，装上酷狗后实测；不可用就只保留「开网页 + 媒体键」。

## 12. Agent 抽象层（为「未来自研」预留）

**问题**：学习 Agent 现在走现成模型 API，将来要换成完全自研的。如果业务代码直接调 `chat.completions`，换的那天要改遍全站。

**做法**：所有 Agent 能力收敛到一个接口，业务层只依赖接口，不依赖厂商。

```ts
type AgentCap = "outline" | "research" | "summarize" | "cards" | "quiz" | "grade";

interface LearningAgent {
  readonly id: string;                    // "api-deepseek" | "local-qwen" | "custom-v2"
  readonly capabilities: AgentCap[];

  planOutline(req: OutlineRequest): Promise<Outline>;
  research?(q: string): Promise<Resource[]>;      // 可选能力：有的实现不联网
  summarize?(text: string): Promise<Summary>;
  makeCards?(chunk: Chunk): Promise<CardDraft[]>;
  makeQuiz?(spec: QuizSpec): Promise<Question[]>;
  grade?(q: Question, a: string): Promise<Grade>;
}
```

**注册与选择**

```ts
const agents = {
  "api-deepseek": new ApiAgent({ provider: "deepseek", tier: "flash" }),
  "local-qwen":   new LocalAgent({ endpoint: "http://127.0.0.1:11434" }),
};
resolveAgent(task, settings); // 按任务类型 + 用户设置 + 可用性挑实现
```

**网关职责**（`agentGateway.ts`，所有调用必经此处）

1. **契约校验**：zod 校验输入输出；模型返回不合 schema 就重试或降级，不让脏数据入库
2. **结果缓存**：`hash(agentId + method + 输入)` → 输出，同样的活不付两次钱
3. **计量与预算**：每次调用记 token 与费用；超月度上限直接拒绝并提示
4. **超时降级**：自研 / 本地 agent 超时或不可用 → 回退到 API agent
5. **审计日志**：记录每次调用的入参出参摘要，便于对比两版 agent 的效果

**验收标准**

- 新增一个实现（哪怕只是 `MockAgent`）**不需要改任何业务代码**
- 设置里能一键切换 agent
- 同一输入能并排对比两个 agent 的产出

**为什么现在不做完整框架**：接口 + 网关在 P5a 顺手写掉（约 0.5 人日）即可。真正自研时，只需要新写一个实现类并注册进去——这才是「可替换」的含义。

### 12.1 为「自训模型」准备的两个数据资产

用户的目标是自己训练模型，那么现在就要开始积累两样东西（成本极低，越早越好）：

**① 调用档案（未来的训练语料）**

网关把每次调用的 `agentId / method / 输入摘要 / 输出全文 / 耗时 / 分数` 写进 `agent_call` 表。日积月累就是一份"真实场景 + 人类满意度"的语料——比网上找的数据集相关得多。

**② 评测集（没有它就无法判断进步）**

从 P5a 起维护 `eval/` 目录，20–50 条样本，每条是「输入 + 期望输出要点 + 打分标准」。用途：

- 换模型、改提示词、微调之后，跑一遍就知道是变好还是变坏
- 避免"感觉好像更聪明了"这种自欺
- 将来 A/B 两个 agent 时，它是唯一的裁判

**③ 训练成本预期（提前知道，别到时候懵）**

- 7B 模型 LoRA 微调：约需 12–24GB 显存，或租云 GPU（按小时计费）
- 从零训练：个人项目不现实，不建议
- 微调后的模型在通用能力上会退化，通常只在窄任务（出题、批改）上强于 API——所以**分任务切换**比整体替换更现实
